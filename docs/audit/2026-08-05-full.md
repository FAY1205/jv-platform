## Executive summary

This is the first full audit since 2026-07-09 and the first with the product live and carrying real customer data, and the overall engineering posture has improved markedly: security headers, error reporting, scheduled jobs, the append-only audit trail, database indexes and the manual-assignment leak that headlined the last report are all closed, and the unit test suite ran green at 1,057 tests. Three things now matter more than everything else. First, a private-notes leak: when an administrator re-routes a lead from one partner to another, the first partner's private notes travel with the lead and become readable by the second partner — I verified this in the code, and the fix is small. Second, the Terms of Service and Privacy Policy that every customer and partner has clicked through since go-live is still placeholder text that admits in its own body that it is placeholder, while the real drafted documents sit unpublished and unlinked. Third, the production database is in Frankfurt, Germany while the published Privacy Policy promises United States storage, and that same live database is also what automated tests point at — so a routine test run could write to or delete real customer data. Below those sit a one-release-behind patch in the web framework's request-protection layer, an administrative unlock endpoint that works across customer boundaries, and a database restore that has never been rehearsed. The written specification has also drifted behind the code — it still describes two deleted database tables, an export column that was removed, and a signup rule that was reversed — which matters because every future work session and audit reads it as the authority. Nothing found suggests the lead-routing engine itself is wrong: it remains pure, deterministic and genuinely well tested, though the rules production actually uses can now silently diverge from the rules the tests check.

**Delta since 2026-07-09 (full):** closed — TR-6 security headers (SEC-08 now met), TR-7 deployment readiness (scheduled jobs, error reporting, trace-ID correlation), TR-5 audit-trail completeness and immutability, TR-8 scale items (batched inserts, indexes, pagination), TR-1 manual-assignment ownership/RLS, TR-10 accessibility core (keyboard rows, focus trap, contrast gates), TR-4 portal Terms gate on data routes. Regressed or newly exposed — production now holds real data, which converts several previously theoretical items (residency, backups, legal text, test-target isolation) into live exposures; specification drift widened as four Accepted decisions shipped without their documented amendments.

## Top risks (ranked)

### R-01: A re-routed lead carries the previous partner's private notes to the new partner
- **Severity:** Critical
- **Verdict:** SPEC-VIOLATION
- **Refs:** PRN-13/NTS-01, PRN-08, SEC-01, ADR-0013 · OWASP API1:2023 (BOLA), ASVS V4.1.3
- **Agents:** audit-tenancy F-1 (sole reporter; **verified by the synthesizer against source**)
- **Evidence:** `src/lib/scope.ts:58-70` — the partner branch of `noteWhere` is `tenant AND authorRole='partner' AND leadId IN (leads I currently own)`. There is **no predicate tying the note to the reading partner**, though the function's own docstring at `:55-57` promises "a partner sees only **their own** partner notes." Ownership moves on re-route: `scope.ts:43-44` `partnerOwnsLead = coalesce(manualPartnerId, partnerId) = me`, and `src/modules/leads/commands.ts:314-334` (`editLead` action `"set"`) re-routes **any** lead with no unmatched-only guard (contrast `manuallyAssignLead:63`). Chain to UI: `src/modules/notes/notes.ts:43-71` → `src/app/api/leads/[ref]/notes/route.ts:21` (shared endpoint) → `src/components/portal-lead-dialog.tsx:141`.
- **Impact:** Partner Y reads partner X's free-text seller notes — competitor-visible commercial information and the field humans paste phone numbers into. Also corrupts first-touch analytics (`src/modules/analytics/partner-performance.ts:157-161`). TST-08 covers admin↔partner only; no re-route case exists, so no test fails today.
- **Remediation:** Add a same-partner-organisation author predicate to `noteWhere` (`inArray(leadNotes.authorUserId, <users of the scope's partner>)`) alongside the existing conditions; mirror in `editLeadNote`. Add TST-08 cases: "a lead re-routed from X to Y does not expose X's partner notes to Y" and the edit mirror. Add a `lead_notes(author_user_id)` index in the same PR (DM-11). Owner decision needed on whether to denormalize `author_partner_id` instead (more robust once Roles/Team ships).
- **Effort:** S (fix) / S (tests) — **WP candidate:** yes, `WP-TEN-1` (the owner decision on status-history, R-22, folds in).
- **Note:** ADR-0013's `FORCE ROW LEVEL SECURITY` revisit is still Draft. This finding is precisely the failure class that would have had a database backstop had it been adopted — keep the standing marker open.

- **Evidence:** Two independent breaks in the same chain of trust.

## Proposed spec amendments

Every EXTERNAL-GAP and SPEC-BELOW-BAR item, consolidated and de-collided, ready for the owner to accept via ADR. **Three ID collisions between agents were reconciled here** — noted inline.

- **AUT-15 (new)** — Post-authentication redirect targets taken from URL, cookie, or body must validate as single-slash-rooted same-origin paths; absolute and protocol-relative targets are rejected in favour of the audience default. *(audit-security F-2. Collision resolved: audit-tenancy also proposed AUT-15; its content becomes AUT-16.)*
- **AUT-16 (new)** — Administrative auth-maintenance actions on tenant-less tables must first prove the target identifier resolves inside the caller's tenant, respond uniformly either way (AUT-05), and write an `audit_log` row. *(audit-tenancy F-2 + audit-security F-1.)*
- **SEC-08 (amend)** — The headers requirement is now met; raise the bar: no `unsafe-inline`/`unsafe-eval` in `script-src` (nonce-based), COOP and CORP served `same-origin`, HSTS `preload` on production only.
- **SEC-09 (new)** — Development-only surfaces hard-404 in production via a server-side `APP_ENV` guard; client-side concealment is never the gate, and `NODE_ENV` is not an environment switch. *(audit-security F-5.)*
- **SEC-10 (new)** — Platform-operator addresses receive only platform-plane events; tenant-plane digests and alerts go to that tenant's own recipients. *(audit-tenancy F-14. Collision resolved: it had proposed SEC-09.)*
- **NTS-04 (new)** — A partner note belongs to the partner organisation that authored it. Re-assigning a lead transfers the lead, never the previous owner's notes. Admin visibility unchanged. Tested under TST-08.
- **PTL-06 (new, only if history transfers)** — Status history transferred with a re-assigned lead is visible to the new owner as lead state; the acting user is never shown to a partner.
- **SCP-06 (new)** — Self-serve admin signup is gated by a single-use, hashed, 48-hour invitation code; **SCP-07 (new)** — a platform-owner tier authorized by environment allowlist gates platform-only surfaces and grants no cross-tenant data access. Amend **SCP-02** accordingly.
- **SEAM-04, PTL-03, EXP-01, EXP-02, §5 Tables, TST-04, SCR-12, AIA-06 (amend)** — Apply the existing DED-01 "Retired (ADR-xxxx)" annotation pattern per ADR-0018/0020/0026/0036/0038; TST-04 becomes "Dedupe-**key** suite: normalization produces a stable grouping key; the pipeline no longer collapses repeats — every row persists as its own lead."
- **EXP-07 (new)** — Every generated workbook records a schema/version marker (a `Run_Summary` row or workbook property) so partner-side positional parsers can detect a column-contract change instead of silently misreading it.
- **EXP-SS (new)** — The export row shape is constructed by exactly one serializer in `src/modules/export`; role-dependent field suppression (the portal campaign blanking) is an explicit, tested option rather than a comment inside a fork.
- **DM-08a (new)** — Any code-resident rule set that affects persisted decisions contributes a **content digest** to the run snapshot; a version label is not a pin.
- **DM-06a (clarify)** — State fallbacks are current-state only; their history lives in run snapshots and the audit log (or, if the owner prefers symmetry with ZIP coverage, add `effective_from`/`effective_to` — the spec must choose).
- **ING-08 / TST-11 (amend)** — Source Profiles are developer-managed; there is no self-serve mapping screen. *Requires the ADR first (R-09).*
- **MLS-04 / PRN-07 (amend or build)** — MLS patterns are read-only and developer-managed until an editor ships with a strict schema that admits no regex or flags keys, a smuggle-rejection test, and DM-08 versioned writes. Any future editor must also validate patterns as linear-time and cap the notes length fed to `exec` (ReDoS precondition, R-70).
- **SET-07 (amend)** — Name `email_outbox`, `idempotency_keys`, and `ai_feedback` explicitly alongside `auth_attempts` as in-scope retention targets; remove the stale `events` clause (dropped by ADR-0020); `audit_log` stays excluded as append-only.
- **LGL-06 (new)** — An admin can redact a single live lead's seller data on a documented data-subject request, using the same redaction patch as void, without requiring a full upload void.
- **ARC-01 (new)** — Architectural invariants are enforced automatically: no `modules`/`lib` → `app` imports (ESLint zones), acyclic dependency graph (madge in continuous integration), proxy closure free of `node:*`. Breaking any fails the build.
- **ARC-02 (new)** — Continuous integration verifies every newly-added dependency against the npm registry (age, downloads, ADR coverage) before merge; failures require human sign-off. *(Slopsquatting gate, VCF-1.10.)*
- **TST-13 (new)** — The integration job fails if any environment-gated suite reports a non-zero skip count, and enforces a test-count floor. *(Collision resolved: audit-devops proposed TST-13 for the smoke tier; that becomes TST-14.)*
- **TST-14 (new)** — A pull-request-time Playwright smoke tier runs on every PR; the full end-to-end journey and Lighthouse gates run on merge.
- **UXQ-01a (new)** — Every async data-fetch error state — not only crash boundaries — renders the server's `traceId` and a Retry action wherever the query is refetchable.
- **UXQ-09 (new)** — Transient toasts pause auto-dismiss on hover and focus, and never dismiss faster than 5 seconds for danger-tone messages.
- **FRM-02a (new)** — A dialog hosting a form with unsaved changes intercepts Escape, backdrop and close-button dismissal with a lightweight discard confirmation.
- **FEP-03 (amend)** — Any surface rendering a full run's lead set without server pagination must virtualize past 200 rows; a single run is not guaranteed bounded once a national week runs unmatched-heavy.
- **FEP-04 (amend)** — Search inputs must own raw keystroke state in a component that does not render the list body; debouncing the committed value alone does not satisfy the rule.
- **MAP-02 (repeat from 2026-07-09, still open)** — Pointer-only components ship native keyboard equivalence or a test-verified companion control; a lint or test rule blocks new call sites omitting both.
- **EXP-06 (test contract, repeat from 2026-07-09, still open)** — Swatch additions ship with a passing pairwise perceptual-distance test in the same PR.
- **FE-DATE (new)** — All user-facing date rendering goes through one `src/lib/dates.ts`; locale policy is decided once.
- **AIA-06 (rewrite)** — Provider-agnostic per-tenant credentials (bring-your-own, ADR-0036); per-tenant token metering from day one; an abuse rate limit on every model-calling path including the credential test. Spend caps and cost display live in the tenant's own provider dashboard, not in-app. **AIA-07 (new)** — Every endpoint that can trigger a provider call records the attempt *before* the call and enforces the per-user rate limit atomically; aborted streams still count.
- **ENGINEERING_STANDARDS §1 (note)** — Auth-throttle 429 responses carry a `traceId` like every other error envelope, or the exemption is recorded. **§1/§6 (amend)** — name where auth use cases live (module, not route handler). **§2 (add)** — a service-role inventory table (file → reason → tenant safety → test) replacing the hardcoded count.
- **DSN-11 (housekeeping)** — Two definitions of DSN-11 exist (the type-scale ladder in FRONTEND_STANDARDS §2 vs. the arbitrary-value rule from the 2026-07-09 report), and SPEC.md has no DSN-11 row at all. Fold the arbitrary-value rule into a new DSN-12 or retire it so the ID means one thing.

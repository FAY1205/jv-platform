# WP-017b: DrizzleRunStore + concurrency (the DB adapter)
Spec: ING-06, PRN-05/08, DM-07/08, DED-03 · Phase: 1 · Tier: A · Depends: WP-017 (core)

## Goal
The DB adapter behind the `RunStore` port: load history/partners through the scope guard,
and persist a run in one advisory-locked transaction with ref-id allocation and the
dedupe_key unique-index reconciliation.

## Definition of done
- [x] `src/modules/run/store.ts` `DrizzleRunStore`:
  - `loadHistory` / `loadPartners` — tenant-scoped reads via `lib/scope.ts` (PRN-08);
    history excludes voided runs (ING-09) and soft-deleted leads.
  - `persistRun` — one transaction that: takes `pg_advisory_xact_lock(hashtext(tenant))`
    first (ING-06 serialization); allocates `UP-YYYY-###` + inserts the upload with rules
    hash/snapshot (DM-07/08); inserts only NEW leads with `LD-YYYY-#####`, using
    `ON CONFLICT (tenant_id, dedupe_key) DO NOTHING` so repeats never duplicate and the
    canonical row + `first_matched_at` are preserved (PRN-05); resolves ref-ids for
    previously-matched keys from the existing rows so the export references them.
- [x] Integration test (`tests/integration/run.test.ts`, self-skips without DATABASE_URL,
  runs in CI / verified live on the dev DB): persist upload+leads with ref-ids + rules hash;
  a re-run of an overlapping lead does not duplicate it and leaves the original untouched.

## Out of scope (→ later)

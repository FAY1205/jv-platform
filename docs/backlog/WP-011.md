# WP-011: Processing lock + idempotency scaffold
Spec: ING-06, API-03 · Phase: 0 · Depends: WP-005 · Tier: B

## Goal
One pipeline run at a time per tenant (queued with visible position), and
idempotency so a retried upload/job never double-processes.

## Definition of done
- [x] `src/modules/pipeline/lock.ts` — `ProcessingQueue` (claim → acquired | queued+position; release promotes the next; per-tenant isolation; re-claim of the active run is idempotent); `InMemoryProcessingQueue`
- [x] `src/lib/idempotency.ts` — `withIdempotency` (runs work once; replays a completed key; rejects an in-progress key); `IdempotencyStore` + `InMemoryIdempotencyStore`
- [x] `idempotency_keys` table (unique per tenant+key) + RLS; migrations 0002 (DDL) + 0003 (RLS) applied to the dev DB
- [x] Tests: idempotency runs-once + replay + in-progress reject; queue acquire/queue/promote/isolation/idempotent-reclaim (6 tests)

## Verification (run — passed)
- `pnpm run check` → 96 unit tests + typecheck + lint green; `pnpm run build` → compiles
- Migrations applied live; verified 22 tables, all RLS-enabled, idempotency_keys + policy present

## Out of scope (→ Phase 1)

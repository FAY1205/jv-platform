# WP-003: Design tokens
Spec: DSN-01/02, PRN-12, SEAM-08 · Phase: 0 · Depends: WP-001 · Tier: B

## Goal
One semantic token source feeding the UI, with the typography roles wired, so
every component consumes tokens (never hardcoded hex) and rebrand/white-label is
a token swap.

## Definition of done
- [x] `src/lib/tokens/tokens.ts` — canonical semantic colors (light+dark), spacing (4/8 grid), radii, elevation 0–3, motion, typography roles, seeded partner palette (SET-02)
- [x] `src/app/globals.css` — CSS variables for light + dark (system preference + explicit [data-theme] override); Tailwind `@theme inline` maps semantic tokens → utilities; base styles; `.num` ledger numerals; focus-visible ring; reduced-motion
- [x] `src/app/layout.tsx` — Inter (body) · Space Grotesk (display) · IBM Plex Mono (mono) via next/font
- [x] Drift guard test: every semantic token has a CSS var + a Tailwind utility; light/dark parity; partner palette locked, valid, unique

## Verification (run)
- `pnpm run check` → 16 tests green; `pnpm run build` → compiles
- Rendered `/gallery` in the browser: light + dark themes swap cleanly; fonts load

## Out of scope (→ later WPs)
- CSS-from-tokens codegen to replace the test-based drift guard (WP candidate)
- Export legend + email template consumption of tokens (Phase 1/2)

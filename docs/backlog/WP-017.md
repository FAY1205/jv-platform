# WP-017: Run orchestration core (the spine's conductor)
Spec: DM-08, PRN-01/05/15, DED-03 · Phase: 1 · Tier: A · Depends: WP-013..016

## Goal
Compose the pure engines into one persisted-run plan, stamp first_matched_at from an
injected clock, build the rules snapshot, and render the export — all behind an injected
`RunStore` port so the orchestration logic is unit-testable without a database.

## Split (per plan)
This WP is the **core** (domain logic + port), fully locally-TDD'd. The DB **adapter**
(`DrizzleRunStore` + `pg_advisory_xact_lock` serialization ING-06 + table-backed
idempotency API-03 + the `dedupe_key` unique-index reconciliation + integration test)
is **WP-017b** — it can only be verified against Postgres (CI), so it is kept separate
so this WP stays 100% green locally.

## Definition of done
- [x] `src/modules/run/plan.ts` — pure `planRun(rows, profile, rules, history)` composing
      apply→normalize→MLS→recode→assign→dedupe + summary (PRN-01; new leads carry
      firstMatchedAt=null).
- [x] `src/modules/run/snapshot.ts` — `buildRulesSnapshot()` (DM-08): deterministic,
      order-independent hash + stored snapshot of the rule set.
- [x] `src/modules/run/process.ts` — `processRun(input, deps)`: loadHistory → planRun →
      stamp first_matched_at via injected clock → buildRulesSnapshot → store.persistRun →
      renderExport of the delivered (kept) leads. `RunStore` port defined here.

## Out of scope (→ WP-017b / later)
`DrizzleRunStore` (loadHistory/loadPartners/persistRun with scoped writes + ref-id
allocation + ON CONFLICT dedupe_key handling); advisory-lock serialization; idempotency;
file Storage + signed URLs (EXP-05) + HTTP route + upload UI (WP-020); void-run (WP-018).

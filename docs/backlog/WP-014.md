# WP-014: Assignment engine (ASN-01/02/03)
Spec: ASN-01/02/03, PRN-01 · Phase: 1 · Tier: A · Depends: WP-013 (normalize, sources)

## Goal
A PURE `assign()` that routes a normalized lead by ASN-01 precedence with ZERO
special-case partner code (ASN-02). Regional exceptions (Virginia Beach, Philadelphia
metro) emerge purely from the ZIP map — never from a name conditional.

## Phase-1 runtime note (owner-confirmed 2026-07-07)
The engine implements full ZIP precedence, but Phase 1 runs with `coverage.byZip`
EMPTY — only the 4 state fallbacks (SC/VA/NJ/CT) are loaded. So a national file routes
in-state leads to the state fallback and everything else to unmatched. Real ZIP coverage
import is deferred (to be discussed). The golden mirrors this runtime; `assign.test.ts`
proves the ZIP path for when coverage is loaded (Phase 2).

## Definition of done
- [ ] `src/modules/pipeline/assign.ts`: `assign(zip5, state, coverage) → { partnerId|null, matchMethod, matchedOn }`
      and `buildCoverage(zipRows, stateRows)` — pure, no I/O/Date (PRN-01). Engine sees partner
      ids as opaque strings only (ASN-02).
- [ ] Precedence: exact `zip5` in `byZip` → `zip`; else `state` in `byState` → `state_fallback`; else `none` (null).
- [ ] `matchedOn` carries the deciding zip5/state for the per-lead audit.
- [ ] Extend the synthetic-week golden with per-lead **assignment** outcomes (empty byZip + the 4
      state rules) → asserts the state-fallback + unmatched mix a national week produces.

## Out of scope
Persisting `partner_id`/`match_method` and the audit_log entry (WP-017); the real coverage
importer + coverage screen (deferred / Phase 2); the Unmatched view UI (WP-021); dedupe (WP-015).

with no special-case code** · ASN-03 unmatched exposes zip/state · PRN-01 determinism ·

# WP-024a: Auth hardening — throttling · lockout · CSRF token
Spec: AUT-03, AUT-04, AUT-12 (token) · Phase: 2 · Tier: A · Depends: WP-023, WP-007 (lockout primitive)
## Goal
Rate-limit + progressively lock the login endpoint, notify on lockout, alert admins
on sustained abuse, and complete AUT-12 with a double-submit CSRF token across all
state-changing routes. Reset/sessions/logout-all land in WP-024b.
## Definition of done
- [x] `auth_attempts` table + migration (0004) + deny-by-default RLS + indexes
- [x] Pure sliding-window `rateDecision` (AUT-03) + `evaluateThrottle` (IP + identifier)
- [x] Progressive `lockoutGate` composing the built `lockoutState` with time-since-last-failure (AUT-04)
- [x] `AuthAttemptsStore` (record / snapshot / clearFailures / ipFailureCount)
- [x] Login route: throttle → 429 + Retry-After; record attempt; lockout email (sink); anomaly alert to admins
- [x] `POST /api/admin/unlock` (admin-only) clears an identifier's failures (AUT-04)
- [x] CSRF double-submit token: proxy issues readable `__Host-jv-csrf`; `assertCsrf` on change-password/logout/void/upload; client `csrfHeaders()` (AUT-12)
- [x] Live-verified: 5×401 → 429 Retry-After 30→29; CSRF issue + reject-without-token + accept-with-token
## Out of scope (→ WP-024b)
Password reset (AUT-06), app-owned sessions registry + list/revoke (ACC-02),
sign-out-all-devices + guaranteed server-side revocation (AUT-14), session-fixation
test (AUT-07). Reset/OTP endpoints get their own throttle wiring there. Admin unlock
UI → WP-034 (activity screens). Real lockout/anomaly email delivery (Resend outbox) → WP-028.

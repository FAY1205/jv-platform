# WP-018: Void-run (ING-09)
Spec: ING-09, DM-04, PRN-05/08 · Phase: 1 · Tier: A · Depends: WP-017b

## Goal
An admin can soft-void a processed run (wrong file / wrongly-confirmed mapping) with a
required reason. Voided leads are excluded from future dedupe (and analytics/exports),
but stay visible in history as voided. Audited.

## Definition of done
- [x] `src/modules/run/void.ts` `voidUpload(scope, ref, reason)`: one transaction sets
      `status='voided' + voidReason + voidedAt` and appends an `audit_log` row
      (DM-04). Leads are NOT deleted (PRN-05 — soft-void, not a history rewrite).
      `UploadNotFoundError` (404) / `AlreadyVoidedError` (409).
- [x] `POST /api/runs/[ref]/void` — Zod `{ reason: min 3 }`, scoped (PRN-08), uniform errors.
- [x] Results-page void action: danger-styled button → Modal with required reason → confirm;
      voided run shows the `voided` badge + a banner with the reason. `voidReason` surfaced in the detail payload.
- [x] Integration test (`tests/integration/void.test.ts`, self-skips): void sets status/reason/
      voidedAt + writes the audit row; **the voided lead disappears from `loadHistory`** so it can
      never mark a future lead previously-matched (the ING-09 poison-prevention). `AlreadyVoided` rejected.

## Verification
typecheck + lint + 181 unit tests + build green. **Integration self-skips (dev DB was DNS-unreachable
this session); run live with `node --env-file=.env.local ./node_modules/vitest/vitest.mjs run tests/integration/void.test.ts` when the DB is back.** The dedupe-exclusion it relies on (`loadHistory` filters `status != 'voided'`) is already live-verified (WP-017b).

## Out of scope / follow-ups
Partner correction notices + portal count updates (Phase 2 — no portal/notifications yet); un-void /
restore; global analytics exclusion of voided runs (Phase 3). **Follow-up (schema):** to allow
RE-uploading a corrected lead whose dedupe_key belonged to a voided run, the `leads(tenant, dedupe_key)`
unique index should become partial (`WHERE deleted_at IS NULL`) and voiding should soft-delete the leads
— today the physical row still holds the key (dedupe VERDICT exclusion works; physical re-insert would conflict).

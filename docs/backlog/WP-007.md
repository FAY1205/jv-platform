# WP-007: Auth hardening baseline (TST-12)
Spec: AUT-01..07, 09, 12–14, PTL-01 · Phase: 0 · Depends: WP-005 · Tier: A

## Goal
The application-layer auth hardening the spec assigns to us (the §6.18 "delegation
boundary"), as pure, injectable, fully-tested primitives — the Supabase route
wiring plugs into these when the portal is built (Phase 2, PTL-01).

## Definition of done (all in src/lib/auth/)
- [x] `constant-time` — timingSafeEqualStr for all secret checks (AUT-09)
- [x] `cookies` — __Host- prefix, HttpOnly, Secure, SameSite=Lax (AUT-12); clear on logout (AUT-14)
- [x] `enumeration` — uniform message + uniform-timing wrapper (AUT-05)
- [x] `lockout` — progressive, finite, notify-on-first-lock (AUT-04)
- [x] `otp` — 6-digit generate + hashed store + constant-time verify + expiry (PTL-01, AUT-09)
- [x] `password` — min length 12 + zxcvbn ≥ 3 + HIBP k-anonymity breach check (AUT-02)
- [x] `reset-token` — single-use, hashed at rest, 30-min expiry (AUT-06)
- [x] `refresh` — rotating tokens + reuse detection → revoke family; 30-day cap (AUT-10); revokeFamily = logout (AUT-14)
- [x] TST-12 suite (10 tests): constant-time, cookie flags, enumeration uniformity, progressive lockout, OTP constant-time, password strength+breach, reset single-use, refresh reuse revokes family

## Verification (run)
- `pnpm exec vitest run tests/unit/auth.test.ts` → 10 tests
- `pnpm run check` → 90 unit tests + typecheck + lint green; `pnpm run build` → compiles

## Out of scope (→ Phase 2, PTL-01)
- Supabase server client (@supabase/ssr) + real login / email-OTP routes + middleware
- Auth tables (auth_sessions, login_attempts, password_reset_tokens, email_otps) + their RLS — added when routes are built; primitives already take injectable stores
- Populating JWT app_metadata claims (tenant/role/partner) that the RLS policies read
- MFA TOTP (AUT-08), CAPTCHA (AUT-11), rate-limit store (AUT-03) — wired with the endpoints

# WP-024b: Auth hardening — password reset · logout scopes · session-fixation
Spec: AUT-06, AUT-14 (self), AUT-07 · Phase: 2 · Tier: A · Depends: WP-024a, WP-007 (reset-token primitive)
## Goal
Self-service password reset (single-use hashed token, revoke-all-on-reset,
notification), server-side sign-out scopes (this/other/all devices), and a
session-fixation guarantee. Uses Supabase's own session model (mirror approach,
ADR-0009) — no app-owned refresh layer yet.
## Definition of done
- [x] `reset_tokens` table + migration (0005) + deny-by-default RLS + indexes
- [x] `ResetStore` (persist/findByHash/markUsed); reuses the built `reset-token.ts`
- [x] `POST /api/auth/reset/request` — uniform + timing-floored (AUT-05), rate-limited (AUT-03, kind=reset), emails link via sink
- [x] `POST /api/auth/reset/confirm` — verify single-use token → strength+breach gate → set password → revoke ALL sessions → notify → mark used (AUT-06)
- [x] `/forgot` + `/reset` pages (component library); "Forgot password?" link on /login
- [x] Logout scopes (AUT-14): local / others / global via Supabase `signOut({scope})`
- [x] Session-fixation test (AUT-07): each sign-in mints a fresh token
- [x] Breach check fails open on HIBP outage (strength still enforced)
- [x] Live-verified: reset request uniform (real vs unknown), bogus/reused token → 400, full happy path (confirm → new pw works, old fails, single-use)
## Out of scope (→ WP-025, needs the app-owned refresh layer)
ACC-02 sessions **list UI** + **precise per-device revoke** and **admin-revokes-partner-sessions**:
Supabase's admin API only supports self-scoped or global sign-out (not userId-based
per-session revocation), so a true device registry with per-device revoke needs the
rotating-refresh layer (`refresh.ts`) — which lands with AUT-10 trusted-device in WP-025.
Real reset/notification email delivery (Resend outbox) → WP-028.

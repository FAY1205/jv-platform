# WP-010: Source Profile parser + drift diff
Spec: ING-01..08, SEAM-05, DM-08 · Phase: 0 · Depends: — · Tier: A

## Goal
Pure header-signature detection and drift handling: exact match auto-applies,
partial match is surfaced as a diff-and-confirm (never silently re-guessed),
missing required columns hard-block, and confirmed drift makes a new version.

## Definition of done
- [x] Types: `CanonicalField` (ING-03), `SourceProfile` (signature, mapping, requiredColumns, strictness, version)
- [x] `detectProfile` → exact | drift | missing_required | unknown (ING-02/08); flexible allows extras, strict blocks them
- [x] `diffHeaders` (added/removed/1:1 rename proposal); `createNextVersion` bumps version without mutating the original (DM-08)
- [x] `applyProfile` maps canonical fields + preserves the full source row (DM-02); `findRowErrors` flags missing Zip AND State (ING-04)
- [x] Seed `GENERIC_PROFILE` (SEAM-05) mapping the canonical column set
- [x] TST-11: exact auto-applies; renamed → diff; added passes flexible / blocks strict; missing Zip hard-blocks; confirmed drift → v+1; 11 tests green

## Verification (run)
- `pnpm exec vitest run tests/unit/sources.test.ts` → 11 tests
- `pnpm run check` → 77 tests total + typecheck + lint green; `pnpm run build` → compiles

## Out of scope (→ later WPs)
- Reading .xlsx/.csv into rows (SheetJS in a Web Worker, FEP-06) — engine takes parsed headers/rows
- source_profiles DB table + the inline mapping / drift-confirm UI (WP-005 schema; Phase 1/2 UI)
- Pinning profile version into the run's rules snapshot hash (Phase 1 spine, DM-08)

## Notes
Rename detection is a deliberate 1:1 heuristic (one removed + one added). Multi-column
reshuffles surface as added/removed lists for the admin to map — never auto-guessed.

# WP-029: In-app notification center + per-event preferences (NTF-04/05, SET-03)
Spec: NTF-04/05, SET-03 · Phase: 2 · Tier: B · Depends: WP-028a (run fan-out), WP-026 (status update)
## Goal
Both roles get an in-app notification center (unread badge, list with deep links,
mark-read). Per role + event, the admin chooses email / in-app / both (NTF-05,
SET-03: digests on, status-change alert email off). The run fan-out and status
changes now emit in-app notifications alongside (pref-gated) email.
## Definition of done
- [x] `src/modules/notify/prefs.ts` — pure `DEFAULT_NOTIFICATION_PREFS` (SET-03), `resolvePref`, `mergeNotificationPrefs`, `NotificationPrefsSchema`, `NOTIFICATION_EVENTS`; settings-backed `load/saveNotificationPrefs` (one `settings` row per tenant)
- [x] `src/modules/notify/notifications.ts` — `createNotification`, `listNotifications`/`unreadCount`/`markRead`/`markAllRead` (scoped to tenant + recipient user id, PRN-08)
- [x] `enqueueRunDigests` now pref-gates email + creates in-app notifications for the partner's & acting-admin's user (`adminUserId`, `prefs` opts; absent = 028a email-all behavior)
- [x] `notifyStatusChange` — admins alerted on a partner status change (in-app default on; email default off, SET-03)
- [x] Routes: `GET /api/notifications`, `POST /api/notifications/[id]/read`, `POST /api/notifications/read-all`; `GET/PUT /api/settings/notifications` (admin, CSRF)
- [x] `NotificationBell` component (badge + dropdown + deep links + mark-read) in the admin TopBar + portal landing; `/settings/notifications` admin page; `/settings` proxy-protected
- [x] Live-verified: 3 integration tests (scoped run fan-out for partner+admin; prefs gating; status-change alert); app E2E (upload → admin run_summary notification, prefs GET/PUT persists, mark-all-read)

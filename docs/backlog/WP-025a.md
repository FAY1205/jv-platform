# WP-025a: Partner onboarding — invite → email-OTP → ToS
Spec: PTL-01, LGL-01, AUT-05/09 · Phase: 2 · Tier: A · Depends: WP-023/024, WP-007 (otp primitive)
## Goal
Passwordless partner sign-in: admin invites a partner → branded email → 6-digit
email-OTP establishes a Supabase session → first login requires ToS/Privacy
acceptance → partner activated. Same email+code every login. All email via the
SEC-07 sink. Scoped portal views (PTL-02/03/04) are WP-026.
## Definition of done
- [x] `otp_challenges` + `tos_acceptances` tables (migration 0006, deny-by-default RLS + indexes)
- [x] Pure `otpOutcome` (expiry/single-use/attempt-cap) + `needsTosAcceptance` gate (unit-tested)
- [x] `OtpStore` + ToS store; partner `provisionPartnerUser` (no password, role=partner + partner_id)
- [x] `POST /api/admin/partners/[id]/invite` — admin-only, creates auth user + status→invited + branded email
- [x] `POST /api/auth/otp/request` — uniform + timing-floored + rate-limited (kind=otp), emails code via sink
- [x] `POST /api/auth/otp/verify` — constant-time verify → **session via admin.generateLink→verifyOtp (Option B, no Supabase email)** → reports tosRequired
- [x] `POST /api/auth/tos/accept` — records acceptance (LGL-01), promotes invited→active
- [x] `/portal/login` (email→code), `/portal/tos`, `/portal` (server-side ToS gate); proxy protects `/portal` except `/portal/login`
- [x] Live-verified E2E: wrong code→400, correct→200+session, /portal→307 ToS gate, accept→200, /portal→200, status→active

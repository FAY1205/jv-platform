# WP-031a: Per-partner coverage entry (CVG-01, DM-06)
Spec: CVG-01, DM-06/08, PRN-05 · Phase: 2 · Tier: A · Depends: WP-030 (partners)
## Goal
Owner-steered model: coverage is entered ON the partner — when adding/editing a
partner, you type the ZIP codes (and optional whole states) they cover. The entry
is that partner's COMPLETE set: new ZIPs are added, a ZIP owned by another partner
is reassigned, and omitted current ZIPs are removed — all versioned (DM-06),
audited, and affecting future runs only (PRN-05). Bulk spreadsheet import + version
history/rollback (CVG-01 bulk, CVG-03) is the sibling WP-031b.
## Definition of done
- [x] `src/modules/coverage/parse.ts` — pure `parseZipList` (NRM-01 normalize, 3–5 digit group, dedupe, invalid tokens surfaced) + `parseStateList` (normalizeState → 2-letter)
- [x] `src/modules/coverage/diff.ts` — pure `diffPartnerCoverage` (add / reassign / keep / remove vs current)
- [x] `src/modules/coverage/commands.ts` — `setPartnerCoverage` (ONE txn: close changed current ZIP rows + open new versions; upsert/delete state rules; audited). Cross-partner reassign closes the other partner's current row first (respects the unique-current-ZIP index)
- [x] `PUT /api/admin/partners/[id]/coverage` (admin + CSRF) — parses raw text, **rejects unrecognized tokens** (400 + invalidZips/invalidStates) so a typo can't silently drop coverage, then applies
- [x] `listPartners` roster shows `zipCount` / `stateCount`; partner detail returns current territory
- [x] Partner form: Coverage ZIPs + states fields (prefilled on edit from current territory), saved after the contact save
- [x] Live-verified: 3 integration tests (add / reassign-versioned / remove-all + state removal); app E2E (create → invalid token 400 → valid apply → roster counts → edit removes → cleanup)
